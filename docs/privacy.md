# Privacy and data handling

[العربية](privacy.ar.md) · [Start here](../README.md)

## What is in this repository?

Reusable Markdown instructions, blank English/Arabic templates, agent metadata, a clearly fictional example and public promotional artwork. It contains no real project briefs, customer records, device paths, credentials or account bindings. The optional design resources are links, not bundled third-party software.

## What does the agent read?

The product definition, current marketing site, relevant project instructions and the files needed for your requested task. You choose the project and scope. Remove secrets and unrelated client/business information before sharing a brief externally. Keep real private research and review evidence outside public Git history.

## Where can data go?

Your agent/model processes the context it reads under that provider's settings. Browsing public sources uses the browser/search service. A builder such as Lovable receives only the brief/assets you actually transfer. Implementation can use the project's existing services; a preview branch is not proof of an isolated database. This skill does not promise that model processing is local or offline.

There is no bundled telemetry, executable helper, installer or background monitor. Downloading or installing the instruction folder does not connect hosting, provision accounts, deploy a website or add analytics.

## Forms, tests and publishing

Establish the real backend destination before submission tests. Use authorized test data and preserve live customer records. Do not send messages, run paid services, connect accounts or publish simply because a brief was approved. Robots and `noindex` do not protect private data; real access controls remain necessary.

The maintenance snippet makes website consistency part of approved repository work. It does not create an automatic publishing permission or a schedule.

## When sharing your version

Export only reusable files you deliberately reviewed. Exclude filled briefs with private facts, local profiles, raw chats, private screenshots, environment files, tokens and unrelated history. Inspect actual image pixels and metadata as well as text. Public issues should use synthetic examples.
